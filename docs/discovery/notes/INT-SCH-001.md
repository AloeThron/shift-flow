## Hard rules ที่ยืนยัน

| หัวข้อ                   | มี   | ค่า/รายละเอียด                                                       | Source                            |
| ---------------------- | --- | ------------------------------------------------------------------ | --------------------------------- |
| min rest               | ✓   | 11 ชั่วโมง                                                           | การจำลอง; รอ HR/นิติกรยืนยัน           |
| max rolling hours      | ✓   | ไม่เกิน 16 ชั่วโมงใน rolling 24 ชั่วโมง                                  | การจำลอง; รอ HR/นิติกรยืนยัน           |
| max consecutive nights | ✓   | ไม่เกิน 3 เวรดึกติดกัน                                                  | การจำลอง; รอ Lab Head/HR ยืนยัน      |
| night → day transition | ✓   | พักอย่างน้อย 11 ชั่วโมงก่อนเริ่ม day shift                                 | การจำลอง; รอ HR/นิติกรยืนยัน           |
| competency valid       | ✓   | ต้อง valid ครอบคลุมตั้งแต่เริ่มจนจบ assignment                            | การจำลอง; รอ Quality ยืนยัน          |
| coverage ขั้นต่ำ           | ✓   | ตาม headcount ของ bench; chemistry เวรดึกอย่างน้อย 2 คนและมี lead 1 คน | การจำลอง; รอ Lab Head/Quality ยืนยัน |

| ชั่วโมงงาน      | เวลาของ assignment ที่อยู่ในเวลางาน ไม่นับ break ที่ไม่จ่าย                     |

## Top 3 pain points

1. Excel หลายไฟล์ทำให้ตรวจ overlap, rest และ coverage gap ได้ช้า
2. Competency matrix กับวันหมดอายุไม่เชื่อมกับตาราง จึงเสี่ยงตรวจไม่ทัน
3. การแก้ sick leave และ swap หลัง publish ต้องแก้หลายจุดและแจ้งคนหลายช่องทาง

---

## Edge cases / open questions

- เวรดึกข้ามรอบต้องดึง assignment จากรอบก่อนหน้าเพื่อตรวจ rest
- หาก competency หมดอายุระหว่างเวร ระบบควร block ตั้งแต่ draft และบอกผู้อนุมัติอย่างไร
- กรณี coverage ขาดจากเหตุฉุกเฉิน ต้องบังคับ reason, approver และ expiry ในหน้าจอเดียวหรือไม่
- ต้องยืนยันค่าชั่วโมงและกติกา OT กับ HR/นิติกร และยืนยัน competency กับ Quality
